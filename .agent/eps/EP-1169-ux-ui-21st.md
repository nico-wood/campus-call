## Objective

Raise the perceived quality of the Campus Call board, market detail, portfolio, and leaderboard screens by adapting five families of modern component patterns from 21st.dev — pointer-tracked spotlight/glow effects, premium background depth, animated/shine outlines, shimmer/press-state buttons, and animated stat graphs (sparklines, chart area fills, number-ticker stat tiles) — **ported by hand to the repo's existing vanilla-CSS variable system (`src/app/globals.css`) and plain React components**, with zero new dependencies, zero behavior changes, and every effect carrying a `prefers-reduced-motion: reduce` fallback. The app already had a restrained "premium dark-green + gold" pass (and an earlier flashier aurora was explicitly rejected for looking "AI-made" — see the comment at `src/app/globals.css:163`), so this EP *improves and deepens* the existing look; it does not redo it, and every effect is tuned for restraint (low alpha, slow cycles, small translations). The EP also folds in four live-smoke findings that ship first: the home board shows too much at once (fixed by Polymarket-style horizontally scrollable category rows, T10), the floating combo slip needs to behave as an optional tray that never covers card actions (T11, building on the `96ed84c` hotfixes), the production mobile UI is not friendly (user report, 2026-11-15) — undersized touch targets, a crowded header/shell, and cards that strain to read at phone widths (fixed by a dedicated presentation-only mobile UX pass, T12) — and cards don't say enough about what each market is about (user report, 2026-11-15: "too many items don't give enough info about what you're forecasting on, basketball game, etc."), fixed by surfacing the `summary` and the event `teams` context the data files already carry (T13, presentation only — no data file is edited).

### C2. Porting rule (no Tailwind, no component library — ever)

21st.dev components ship as Tailwind/shadcn registry items, often with framer-motion. **None of that code is installed or copied.** Each task below names the specific 21st.dev source pattern it adapts, and the implementation is a from-scratch port to:

- CSS on the existing custom properties in `src/app/globals.css` (`--bg`, `--surface`, `--surface-raised`, `--border`, `--emerald`, `--accent`, `--gold`, `--gold-soft`, `--gold-line`, `--negative`, `--focus`, `--motion-fast`, spacing/radius tokens). No new hardcoded palette colors; derived tints use `color-mix(in srgb, var(--token) N%, transparent)` like the file already does.
- Plain React function components / hooks in the repo's existing style (see `src/app/local/number-ticker.tsx` for the house pattern: small, documented, reduced-motion aware).
- `npx shadcn add ...`, `npm install <anything>`, or pasting Tailwind class strings is a constraint violation. **Zero new dependencies** (`dependencies` and `devDependencies` in `package.json` unchanged). Charts and sparklines stay hand-rolled inline SVG — no chart library.

### C3. Accessibility and performance (every task)

- Every animation or pointer effect specifies and implements a `prefers-reduced-motion: reduce` fallback (static or removed), following the existing house pattern (`.activity-ticker`, `.market-card`, `NumberTicker` already do this).
- Animations use **transform and opacity only** (plus `background-position`/custom-property interpolation that never triggers layout). No animating of width/height/top/left/margin/padding. No layout thrash.
- Pointer-tracking handlers are throttled through `requestAnimationFrame` (one pending frame max) and write either scoped CSS custom properties on the hovered element (T1) or a compositor-only inline `transform` via ref (T4), or compositor-only scoped custom properties consumed by a CSS `transform` (T9 — an inline transform there would outrank T2's `.confirm:active` press state); they never call `setState` per pointermove, and never write an inherited custom property on `document.documentElement`.
- Hover/pointer effects are gated behind `@media (hover: hover) and (pointer: fine)` so touch devices keep the current behavior.
- `:focus-visible { outline: 2px solid var(--focus) }` (globals.css:131) keeps working on every control touched; no `outline: none` anywhere.
- Contrast stays on existing theme tokens; gold stays a restrained accent, never a button fill or body text color (globals.css:6–9).
- T12 re-verifies every row above as a device-level smoke pass on a mobile viewport (390×844 emulation): pointer/hover effects inert on coarse pointers, reduced-motion fallbacks active, and ≥44×44 CSS px touch targets at ≤40rem.

### C4. SSR-safety rule (test-driven)

`tests/hackathon-door.test.ts` renders `HomePage` with `renderToStaticMarkup`. Any new client component or hook used on home must render valid markup server-side without touching `window`/`document` during render (browser APIs only inside `useEffect`/event handlers — the house pattern in `number-ticker.tsx` and `member-widget.tsx`).

### C5. Known layout bug guard

A list must not carry both `.frame` and `margin: 0` (cancels `margin-inline: auto`; see AGENTS.md "Frame inset"). No task below adds `.frame` to any element.
